# Фактура интерактивного учебника Java ВШЭ

Порядок тем и образовательные результаты взяты из [программы курса, весна 2027](https://docs.google.com/spreadsheets/d/11MM7ju7x_1D5E_CU_CQZMC0GvxWvccW_Ub2VNEN-P0c/edit?gid=502246308#gid=502246308). Каждая глава даёт 15–30 минут работы с отдельными короткими примерами до или после семинара. Проектные ДЗ и рубежный контроль идут по программе курса.

В каждой карточке есть результат, короткая теория, конкретный файл для работы, публичная проверка, подсказка и вопрос о новом случае. Перед запуском упражнения студент может сформулировать ожидаемый результат. После выполнения он сам вызывает проверку. Состояние хранится локально в его копии репозитория. Ошибка ведёт к подсказке и новой попытке. Для прохождения нужны работающий результат и ответ на вопрос.

## Главы и упражнения

| Тема | Упражнения в IDE | Как увидеть результат |
|---|---|---|
| **1. Платформа Java** | **MVP:** вычислить секунды из минут, пройти цепочку `javac → .class → java`; вызвать существующий метод и найти `invokestatic` через `javap`. Следующее упражнение для главы: сравнить сведения из `java -version` и `javac -version` в двух окружениях. | Проверить вывод на нескольких входах и фактическую инструкцию в байт-коде. Объяснить, почему после правки исходника без повторной компиляции старый класс ведёт себя так же. |
| **2. ООП в Java** | **MVP:** перенести ответственность за остаток в метод объекта склада; использовать переданную политику доставки через интерфейс. Следующее упражнение: сравнить композицию и наследование на платном и бесплатном тарифах. | Убедиться, что отказ в резерве сохраняет остаток и клиент работает с тремя политиками. Объяснить, какие изменения нужны для подключения четвёртой. |
| **3. Структуры данных** | Устранить логические дубликаты в `HashSet`; выбрать `List` или `Set` по требованиям к порядку и повторениям; исправить типобезопасное копирование коллекции с ограниченными wildcard. | Тесты с равными ключами, порядком, повторениями и разными параметрами типов. Объяснить, что произойдёт при мутации ключа в хеш-коллекции. |
| **4. Ввод-вывод и файловая система** | Прочитать текст в UTF-8 через `Path` и `Files`; обойти дерево временных каталогов; восстановить записи из сериализованного представления. | Проверки на Unicode, пустом файле, вложенных папках и восстановлении данных. Объяснить выбор между чтением всего файла и последовательной обработкой. |
| **5. Исключения и отладка** | Локализовать сбой по цепочке `Caused by`; добавить контекст в исключение; закрыть ресурс при неудачном чтении через try-with-resources. | Проверить тип ошибки, сохранённую причину и факт закрытия тестового ресурса. Найти причину на другом stack trace. |
| **6. Функциональное программирование** | Заменить цикл цепочкой Stream; сгруппировать записи и получить агрегаты; обработать отсутствие результата через Optional. | Сверить расчёт с ручным примером, пустым набором и несколькими группами. Предсказать, когда вычислится резервное значение. |
| **7. Многопоточность** | Воспроизвести потерю обновления с помощью управляемого порядка потоков; защитить операцию; собрать две асинхронные ветки через CompletableFuture. | Проверить счётчик и обработку ошибки ветки. Объяснить, почему `volatile` сам по себе не делает `count++` атомарным. |
| **8. Аннотации и reflection** | Объявить аннотацию с параметром; обнаружить её при выполнении; вызвать только отмеченные методы. | Проверки на retention, список вызванных методов и переданные параметры. Предсказать результат с `CLASS` вместо `RUNTIME`. |
| **9. Spring Framework** | Внедрить репозиторий через конструктор и заменить его тестовой реализацией; диагностировать внутренний вызов `@Transactional`. | Тест контекста и тест на откат после сбоя. Объяснить, какой вызов проходит через прокси. |
| **10. Java 9–24** | Выразить данные через record; обработать закрытую иерархию через switch с pattern matching; запустить пример с виртуальными потоками. | Контроль поведения и заданной версии компиляции. Предсказать результат при добавлении нового подтипа. Базовый JDK курса — 26. |
| **11. Базы данных** | Параметризовать JDBC-запрос; перенести выборку на JPA; воспроизвести и устранить N+1. | Тест с данными, содержащими апостроф, проверка результата и количества SQL-запросов. Объяснить поведение при загрузке нескольких связанных сущностей. |
| **12. Сеть** | Обработать ответ локального HTTP-сервера, включая 404 и тайм-аут; затем обменяться сообщением с локальным TCP-сервером. | Локальные интеграционные тесты с управляемыми ответами, временем ожидания и закрытием соединения. Объяснить разницу между HTTP-ошибкой и обрывом соединения. |
| **13. Сборка и тестирование** | Добавить в Maven или Gradle тест, ловящий заданный дефект; написать интеграционную проверку; подключить проверку качества к CI. | Показать, что тест падает на дефектной реализации и проходит на исправленной. Объяснить, какую зависимость здесь полезно изолировать, а какую стоит оставить реальной. |
| **14. Паттерны проектирования** | Заменить ветвление на Strategy; подключить несовместимый интерфейс через Adapter; добавить Builder там, где есть несколько необязательных параметров. | Поведенческие тесты до и после рефакторинга, тест на новую стратегию. Объяснить, в каком упрощённом варианте структуры хватило бы обычного метода. |

## Авторская проверка главы

Перед публикацией пройти упражнение со стартовым кодом, типичной ошибкой и корректным решением. Наблюдаемые обязательные свойства проверяет код. Вопрос и подсказка должны требовать объяснить следствие на другом случае, который студент ещё не видел в тестовом выводе.

В MVP готовы три упражнения по платформе Java и два по ООП. [Начало первой главы](lessons/01-platform/first-run/lesson.md) рассчитано на 10–15 минут работы в чате. Остальные строки описывают задания для следующей итерации.
